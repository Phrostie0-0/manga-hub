# Архитектура сайта

Статус: начальный проект устройства, 20 сентября 2026 года. Структура ниже планируется; сейчас созданы только README и документы в docs/.

## Стек и локальный запуск

- **Next.js + React + TypeScript:** страницы сайта и серверные обработчики в одном проекте.
- **PostgreSQL:** общий каталог, сведения об источниках, главах и обновлениях.
- **Drizzle + node-postgres:** схема, SQL-миграции и запросы к БД; зависимости и совместимые стабильные версии фиксируются при реализации.
- **Node.js LTS и npm:** общий язык для сайта и адаптеров, один lockfile.
- **Нативный PostgreSQL на macOS:** через согласованный для рабочего Mac способ установки, например Homebrew или Postgres.app. Отдельная база и пользователь для проекта.

В локальной разработке сайт и PostgreSQL слушают loopback-интерфейс. Браузер обращается к сайту, серверная часть — к БД. DATABASE_URL и другие секреты остаются в локальном .env; их не передаём браузеру.

Долгий сбор данных выполняет отдельный Node-процесс из того же репозитория. Сначала он запускается вручную; позже в режиме периодического обновления. Закрытый или спящий Mac не обновляет каталог — интерфейс показывает время последней проверки. Посещение страницы только читает сохранённые данные.

При переносе на VPS сохраняются PostgreSQL и схема. Понадобятся настройка окружения, миграции и перенос данных; автоматический бесшовный перенос не предполагается.

```text
manga-hub/

│   └── SOURCES.md              # факты и решения по площадкам
├── src/
│   ├── app/
│   │   ├── [locale]/
│   │   │   ├── catalog/        # поиск и фильтры
│   │   │   ├── manga/[id]/     # общая карточка произведения
│   │   │   ├── updates/        # лента обнаруженных обновлений
│   │   │   └── sources/        # доступность источников
│   │   └── api/               # только необходимые серверные endpoints
│   ├── components/            # общие элементы интерфейса
│   ├── features/
│   │   ├── catalog/           # поиск, карточки и правила объединения
│   │   └── updates/           # представление обновлений
│   ├── server/
│   │   ├── db/                # подключение, схема и запросы PostgreSQL
│   │   ├── sources/
│   │   │   ├── contracts.ts   # формат данных и возможности адаптера
│   │   │   ├── registry.ts    # разрешённые адаптеры и домены
│   │   │   └── adapters/      # отдельный модуль на подключённый источник
│   │   └── ingestion/         # получение, нормализация, сохранение
│   └── i18n/                  # словари интерфейса ru/en
├── workers/                   # запуск процесса обновления
├── db/migrations/             # версионируемые SQL-миграции
├── scripts/                   # заполнение демоданными и служебные команды
├── tests/                     # проверки сложных правил и импорта
├── public/                    # собственные статические ресурсы
├── .env.example               # имена переменных без секретов
└── package.json
```

Серверные модули источников и БД не импортируются в клиентские компоненты. Пустые каталоги и неработающие файлы-заглушки заранее не создаём: структура появляется вместе с реализацией соответствующих этапов.

## Основные сущности PostgreSQL

| Сущность | Назначение и важные поля |
| --- | --- |
| manga | Внутренний ID произведения; различаем оригинал, адаптацию и отдельное издание |
| manga_titles | Название, язык, вариант написания, источник названия |
| sources | Постоянный код площадки, состояние подключения, результаты проверки условий, reviewed_at |
| source_domains | Проверенные текущий и прежние домены, даты действия, ссылка на подтверждение переезда |
| source_titles | Карточка площадки: source_id, external_id, manga_id (может быть пустым до сопоставления), путь, язык/издание, last_success_at |
| source_chapters | Внешний ID главы, исходная метка главы/тома, язык, перевод/редакция при наличии, дата публикации, first_seen_at, доступность |
| sync_runs | Начало/конец запуска, источник, статус, объём изменений, безопасное описание ошибки |

Уникальные ограничения: source_titles — (source_id, external_id); source_chapters — (source_title_id, external_id). Если площадка не предоставляет стабильного ID, адаптер документирует проверенный устойчивый ключ; домен в него не входит. Источник без надёжного способа идентификации не получает автоматическое объединение записей.

Описание и обложка хранятся или показываются только в разрешённом объёме и способом, допускаемым условиями. Для выбранного значения сохраняются площадка, исходная ссылка и время получения. Право получить данные и право показать их посетителям рассматриваются раздельно.

Главу храним с исходной строковой меткой: «12», «12.5», «спецвыпуск». Количество записей и номер последней главы — разные показатели. Наличие 80 глав на одной площадке и 82 на другой ещё не доказывает наличие двух непрочитанных глав.

Для доступа отдельно храним способ оплаты (free / paid / subscription / unknown), необходимость входа (да / нет / неизвестно), время проверки и известные условия. Вход и платность могут требоваться одновременно. Проверка без аккаунта не сообщает о покупках конкретного пользователя. Нельзя выдавать число видимых на сайте глав за полный объём произведения или мобильного приложения.

Совпадение названия создаёт кандидата на объединение, но не выполняет его автоматически. Проверяем авторов, оригинальные названия, формат, язык/издание и внешние ID. Неуверенные сопоставления сохраняем раздельно до ручной проверки.

## Источники и смена домена

Каждый адаптер сообщает, какие операции он действительно поддерживает: поиск/индексирование карточек, метаданные, список глав, обновления. Не требуем от всех площадок одинаковых возможностей. Административный запуск обновления не открывается анонимным посетителям сайта.

Порядок работы: проверка статуса подключения → запрос по допустимому интерфейсу → валидация ответа → нормализация → транзакционное сохранение → фиксация результата. Частичная ошибка сохраняет последнюю успешную версию и пометку об устаревании.

Ограничения частоты задаются отдельно для площадок по опубликованным условиям или соглашению. При 429 учитывается Retry-After; повторные ошибки увеличивают паузу. Ошибка доступа или неожиданная смена формата приостанавливает соответствующую операцию, а не выдаёт пустой каталог.

Для ReadManga и других переезжающих сайтов идентичность источника отделена от домена. Новый адрес добавляется после подтверждения по проверенному официальному каналу и проверки его условий. Произвольный редирект и найденное поиском зеркало не являются таким подтверждением. Автоматические запросы ограничены проверенными адресами; пользовательская ссылка не запускает произвольную серверную загрузку.

## Языки и личные данные

Интерфейс /ru и /en использует один сервер и одну БД. Язык интерфейса, язык названия и язык доступных глав — разные поля. Переключение интерфейса не делает русские главы английскими. На первом этапе реализуется /ru; /en предусмотрен структурой.

В первой версии нет общих серверных отметок «я прочитал»: анонимные посетители не должны менять прогресс друг друга. Личная библиотека и идентификация её владельца проектируются следующим этапом. При необходимости гостевые отметки могут храниться в браузере с экспортом; основной каталог в любом случае остаётся в PostgreSQL.
