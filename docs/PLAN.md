# План первой версии

Обновлено: 20 сентября 2026 года. Документ описывает будущую реализацию; работающего сайта и адаптеров пока нет.

## Решения

- Продукт — сайт, доступный в обычном браузере с компьютера и телефона.
- PostgreSQL используется с первого дня. Локальная разработка на Mac без Docker и внешнего сервера.
- Первая версия — общий каталог без регистрации и хранения токенов читательских аккаунтов.
- Русский каталог запускается первым. Английский интерфейс и английские источники добавляются в тот же проект после проверки площадок.
- Сначала собираются разрешённые метаданные и ссылки. Страницы глав, изображения страниц манги и переводы не размещаются.

## Основной сценарий

Человек находит произведение по знакомому названию, открывает общую карточку, видит источники, язык, сведения о доступных главах и время их проверки, затем переходит на выбранную площадку.

Показываем только известные сведения. «Не удалось проверить», «неизвестно» и «нет глав» — разные состояния. Бесплатность не выводим из наличия ссылки или возможности открыть карточку.

## Этапы и признаки готовности

| Этап | Что делаем | Когда готово |
| --- | --- | --- |
| 0. Источники и окружение | Уточняем домены и условия; выбираем первый допустимый источник; подготавливаем Node.js и PostgreSQL | Для источника понятны способ доступа, допустимые поля и ограничения. Локальный Postgres доступен приложению |
| 1. Каркас сайта | Next.js, TypeScript, миграции PostgreSQL, небольшая собственная демонстрационная выборка | На localhost открываются каталог и карточка; миграции создают пустую БД с нуля; демоданные явно помечены |
| 2. Каталог | Поиск по вариантам названия, фильтры по площадке/языку, карточка и ссылки | Одно произведение может иметь несколько источников; нет случайных слияний по одному лишь названию |
| 3. Первая интеграция | Ограниченный сбор через разрешённый интерфейс; сохранение происхождения полей; обновление по команде | Повторный запуск не создаёт дублей; ошибки источника видны; посещение сайта не запускает внешний сбор |
| 4. Сравнение источников | Подключаем следующую допустимую площадку, сверяем издания и нумерацию | Видны различия по языку, главам и доступности; неоднозначные соответствия остаются раздельными |
| 5. Лента обновлений | Новые главы по источникам и работа локального процесса обновления | Повторное наблюдение главы не считается новой публикацией; исчезновение карточки не стирает историю |
| 6. Английский каталог | Перевод интерфейса, английские названия и адаптеры с подтверждёнными условиями | /ru и /en используют одну БД; язык интерфейса отделён от языка перевода манги |

Этапы 0 и 1 можно выполнять параллельно: интерфейс и модель данных разрабатываются на собственных демонстрационных данных. Реальный адаптер не запускается до проверки соответствующей площадки. Если выбранный источник не подходит, его статус фиксируется в SOURCES.md, а первый адаптер выбирается из остальных допустимых кандидатов.

## Экраны

1. **Каталог:** строка поиска, карточки, фильтры, пагинация и понятное пустое состояние.
2. **Произведение:** варианты названия, разрешённые описание/обложка, источники, язык и условия доступа, последняя проверка.
3. **Обновления:** изменения по площадкам; отдельно дата публикации и дата обнаружения.
4. **Источники:** подключено / недоступно / на проверке, время последнего успешного обновления.

Если права на обложку или описание не установлены, карточка использует собственную заглушку и разрешённые фактические поля. Отсутствие изображения не блокирует разработку экрана.

## Проверки при реализации

- Для импорта: повторный запуск, неполный ответ, изменённая карточка, несовпадение языка/издания.
- Для глав: 12, 12.1, бонус и главы разных переводов не схлопываются в одно число.
- Для обновлений: сетевой сбой не превращается в удаление всех глав; показывается устаревание данных.
- Для сайта: поиск, переход в карточку и ссылка на источник работают на узком и широком экране.
- Для БД: миграции воспроизводимы; проверяется восстановление из резервной копии перед первым публичным запуском.

## Следующие версии

- Личная библиотека и прогресс: сначала гостевые отметки на устройстве, затем аккаунты и перенос этих отметок в профиль.
- Синхронизация с читательскими аккаунтами через разрешённые интеграции.
- Рекомендации после появления достаточных данных и обратной связи.
- Публичное размещение сайта: собственные доступы, конфигурация, резервные копии и проверка готовности к пользователям.
- Авторские публикации, нейроперевод и мобильный клиент — самостоятельные будущие направления.

Нативный клиент сам по себе не защищает контент от автоматизированного получения. Решение о его разработке принимается по пользе для читателя; контроль доступа и ограничения запросов проектируются на сервере.

## Ближайшая задача разработки

Подготовить локальные Node.js и PostgreSQL, затем создать каркас сайта с миграцией и двумя экранами на демонстрационных данных. При проверке среды 20.09.2026 команды node, npm, psql и postgres не обнаружены в PATH; наличие установленных вне PATH программ ещё нужно уточнить. В этом этапе планирования установка не выполнялась.
