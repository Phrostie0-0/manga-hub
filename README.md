# Manga Hub

Manga Hub — сайт, который собирает личные библиотеки и прогресс чтения из нескольких манга-сервисов в одном профиле.

## Первый MVP

Пользователь:

1. создаёт профиль Manga Hub;
2. один раз подключает аккаунты ReManga и MangaLib через изолированную браузерную сессию;
3. получает импорт тайтлов, уже добавленных в его личные библиотеки, и подтверждённого прогресса чтения;
4. видит одинаковые произведения с разных источников одной записью;
5. дальше получает автоматическое обновление примерно раз в час.

MVP не индексирует полный каталог площадок, не скачивает страницы глав и не содержит читалку. Синхронизация сначала односторонняя: внешние аккаунты → Manga Hub. Сервис не добавляет произведения и не меняет прочитанные главы на подключённых площадках.

## Архитектура

- Next.js, React и TypeScript для сайта и API;
- PostgreSQL и Drizzle с первого дня;
- Better Auth с PostgreSQL-сессиями для профиля Manga Hub;
- Graphile Worker для фоновых заданий без Redis;
- Playwright для входа на источники;
- отдельный sync worker, имеющий доступ к зашифрованным cookies/tokens;
- envelope encryption: отдельный DEK на подключение, KEK вне PostgreSQL.

Локально сервис разрабатывается без Docker: Node.js-процессы плюс нативный PostgreSQL. Для Ubuntu используются те же код, миграции и команды, упакованные в Docker images. Платформенной логики для macOS в проекте нет.

## Что уже работает

- профиль Manga Hub: регистрация, вход и PostgreSQL-сессия;
- страницы подключений и личной библиотеки;
- интерактивный вход в ReManga и MangaLib через отдельный Chromium context;
- импорт только пользовательских списков, статуса и доступного маркера прогресса;
- почасовая фоновая синхронизация через Graphile Worker;
- envelope encryption внешних cookies/token отдельным DEK на подключение;
- идемпотентные PostgreSQL upsert-ы тайтлов, произведений и прогресса.

Первый локальный transport открывает отдельное окно Chromium на компьютере, где запущен worker. Для серверного запуска понадобится `remote-stream` gateway, чтобы показывать это окно внутри страницы пользователя.

## Локальный запуск без Docker

Нужны Node.js 24+, pnpm 11+ и PostgreSQL 17. Если локальных роли и базы ещё нет, создай их один раз (на запрос пароля укажи `manga_hub_dev` либо затем поменяй `DATABASE_URL` в `.env`):

```bash
createuser --login --pwprompt manga_hub
createdb --owner=manga_hub manga_hub
```

После первого клонирования:

```bash
pnpm install
pnpm local:init
pnpm browser:install
pnpm db:migrate
pnpm dev
```

`pnpm dev` одновременно запускает Next.js и worker. Сайт доступен на [http://localhost:3000](http://localhost:3000). При подключении источника worker открывает чистое окно Chromium; пароль вводится только на странице ReManga или MangaLib. После успешного входа окно закрывается, сессия шифруется, а первичный импорт запускается автоматически.

Production-сборка проверяется командами `pnpm build` и `pnpm start`; worker запускается рядом отдельной командой `pnpm worker`. Секреты подаются процессам во время запуска и удаляются из standalone-артефакта после сборки.

Локальные `.env`, `.local/`, browser state и ключи исключены из git. Готовый `.env.example` содержит только имена настроек.

## Текущие ограничения

- Реальный вход в пользовательские аккаунты не выполнялся разработчиком: первый запуск нужно проверить на своих ReManga/MangaLib аккаунтах.
- Адаптеры получают доступный у источника последний marker/count. Они не выдумывают полный набор прочитанных глав, если источник его не отдаёт.
- Refresh token MangaLib пока не обновляется отдельным HTTP flow; после истечения сессии подключение попросит повторный вход.
- ReadManga и InkStory остаются выключены до отдельного технического и договорного решения.
